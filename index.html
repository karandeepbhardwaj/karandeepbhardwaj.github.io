An orchestration system for agents

The best example of how I work is an orchestration system I led in financial services. It sits in front of a high-volume service operation: every request has to be understood, the requester identified and authenticated, and the work routed, across 15+ categories, to the right agent, tool or human, with state kept throughout.

At its core is a LangGraph state machine on Amazon Bedrock: agents and tools coordinated as explicit states and transitions, session state in DynamoDB, and a middleware layer enforcing three tiers of authentication before an agent can act. It took self-serve resolution from 61% to 96%. The platform under it, Lambda, API Gateway, DynamoDB and SQS, handled 200k+ requests a month with no customer-impacting incidents, and automating identity verification cut resolution time by 65%.

Those three numbers are the whole “selected outcomes” section of my old site, with the context put back in.

The system as a state machine. Authenticate is the gate: nothing reaches an agent or a tool before it. Session state in DynamoDB, tool calls over MCP.
